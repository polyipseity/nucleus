# Cross-host feature parity

# Upstream workarounds registry: .agents/instructions/upstream-workarounds.instructions.md

Same capability on every host. Reusable behavior goes in a shared module, not a per-host special case: POSIX is bash under `src/scripts/`, Windows is PowerShell under `src/platforms/Windows/modules/`, and no Windows runtime code names a `.sh` path. A platform difference needs `# WHY:`.

Evaluate macOS (`src/hosts/MacBook/`), NixOS (`src/hosts/NixOS/`), and Windows (`src/hosts/Windows/` plus `src/platforms/Windows/modules/`) before writing, and implement every applicable host in the same change. When parity debt cannot be paid, state implemented now, already in parity, or not practical yet with a `# WHY:` in code. Sweep packages, shell and dev tooling, security, desktop and UI, remote access, secrets, editor, git and signing, power and network, automation.

Desktop and UI work reduces persistent chrome where keyboard workflows cover it and keeps high-signal visibility defaults unless a host constraint forces the loss. State the tradeoff and remaining access path in DSC `directives.description:` or equivalent.

POSIX-shared behavior belongs in `src/modules/*.nix`. Windows prefers a DSC resource, otherwise `src/platforms/Windows/modules/*.ps1` with `apply.ps1` orchestration only. Imperative Windows parity needs both config and cleanup paths, or disabling leaves state behind.

A host-specific script needs genuinely host-specific behavior. Merge macOS and NixOS twins with `builtins.replaceStrings` or `case "$(uname)"`, not prefixes. Configs with native extension points (direnv `lib/*.sh`) use the host `lib/` convention from `app-config-policy.instructions.md`.

## Windows imperative recovery

Config and deconfig paths both touch only declaratively managed blocks, stop on ambiguous ownership or preconditions, converge idempotently, remove only managed state and no-op when gone, and expose an enable/disable toggle wired in `apply.ps1`. macOS and NixOS need no equivalent because Nix removes units on re-apply; Windows does it by hand (`Sync-*Service.ps1` for SCM services, `Unregister-ScheduledTask` in task modules). A new Windows module implements both paths and warns without aborting on failed start.

## Service refresh and packages

Every kill, refresh, and restart goes through `refresh_*` in `src/scripts/lib/macos-launch-services.sh` or `Set-NucleusService.ps1` on Windows, never inline `killall` or `Stop-Service`. macOS activation calls the library through a wrapper under `src/platforms/macOS/scripts/`. Restart each daemon at most once per activation. Services default to persistent daemons with auto-start and crash recovery; oneshots are exceptions classified in `.agents/skills/nucleus-service-reference/references/service-firing-policy.md`. No explicit rate limiting; platform defaults cover it.

A cross-host tool lands in `core.nix` and `system-packages.dsc.yml` in the same change. A tool in both nixpkgs and Homebrew is declared once in `managedPackages` in `core.nix`, never duplicated in host files or `NixOS/desktop.nix`. Windows source builds pin a commit hash in `Build-<Tool>.ps1`. Secrets and wallpapers keep the same shape: `secrets.nix` plus `materialize-user-secrets.sh` on POSIX, `Sync-UserSecret.ps1`, `Sync-SecretFile.ps1`, `Sync-WallpaperInventory.ps1`, and `user.dsc.yml` on Windows, with existing stale cleanup rules preserved. Cloud drives follow `cloud-drives-and-finder.instructions.md`.

## GC, retention, symlinks

GC timing values live at point of use, never a separate manifest. Precedence: CLI flag, per-tool env var, master flag or env, Nix config default, then `7d` / `7`.

Every provisioned symlink is writable and delete-protected where possible (`chflags uchg` macOS, `icacls /deny` Windows). A user-scope Linux activation cannot set the immutable flag (`chattr` needs `CAP_LINUX_IMMUTABLE`, see `chattr(1)`), so NixOS detects instead through step 13 `run_method1_symlink_resolution` and `home.activation.verifyManagedSymlinkPaths`. Platforms that can prevent removal warn rather than abort. Read-only is required for Nix store targets; Windows mirrors POSIX writability. Deviations need `# WHY:`. `macos-symlink-farm.sh` manages `/usr/local/bin` links from `__nucleus_symlink_farm` generated by `src/hosts/MacBook/activation.nix`, and removes only symlinks.

## Imperative code that belongs there

Bootstrap curl before Nix; `defaults write` and macOS restarts; `git clone`, SOPS decryption, and live API calls; package managers; log dirs, PowerShell modules, and Android images with ordering or dynamic URLs; Wi-Fi MAC, PATH, and firewall runtime values; CamillaDSP, heartbeat, and cloud-drive tasks with dynamic ports and config; QtPass, Caddy config, and source builds needing HKCU hives, runtime builds, or git history.

Before merging: all three hosts evaluated, exceptions justified with `# WHY:`, shared logic extracted, and matching instructions updated.
